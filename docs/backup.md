# ~/dev のバックアップ

`scripts/backup-dev.sh` は、`~/dev/` をまるごと外付けドライブなどへバックアップするスクリプトです。

## モード

```bash
bash scripts/backup-dev.sh          # 差分コピー (rsync)。バックアップ先の dev/ を ~/dev/ と同じ状態にする
bash scripts/backup-dev.sh tar      # 日時付きの tar.gz を 1 ファイル作る
bash scripts/backup-dev.sh check    # 未コミット・未 push のリポジトリを確認するだけ（バックアップ先は不要）
```

どのモードでも、最初に各 git リポジトリの未コミット・未 push を表示します。
`node_modules` や `.venv` など再生成できるものと `certs` は除外します（一覧はスクリプト内の `EXCLUDES`）。特定のパスを除外したいときは「決め打ちのパスを除外する」を参照。

## 設定

バックアップ先は PC ごとに違うため、リポジトリには書きません。次のどちらかで指定します。

- `config/backup.conf`（git 管理外）に書く:

  ```bash
  BACKUP_DEST=/path/to/backup
  ```

- 環境変数で指定する: `BACKUP_DEST=/path/to/backup bash scripts/backup-dev.sh`

`BACKUP_DEST` は**保存先フォルダ**です。この中にバックアップができます。保存先より上の階層には何も書きません。

`BACKUP_DEST=/X/backup` の場合:

| モード | できるもの | 備考 |
|---|---|---|
| rsync | `/X/backup/dev/` | `~/dev` の中身がこの `dev/` 直下に入る（`dev/dev/` にはならない） |
| tar | `/X/backup/dev-20261111-1430.tar.gz` | 保存先の直下に 1 ファイル。中身は `dev/` から始まる |

- ドライブ直下や、名前が `dev` のフォルダは指定しないでください（ドライブ直下に `dev/` や tar ができる、`dev/dev/` と二重になる）。専用のサブフォルダを作って指定してください。
- **`BACKUP_DEST` は自動では作りません。** 外付けドライブが接続されていないときに、本体側へ偽のバックアップ先を作ってしまうのを防ぐためです。初回は手動で作成してください。存在しなければスクリプトはエラーで止まります。

### 決め打ちのパスを除外する

`node_modules` などの名前による除外（スクリプト内の `EXCLUDES`）とは別に、特定のパスを `config/backup.conf` で除外できます。

```bash
BACKUP_DEST=/path/to/backup
BACKUP_EXCLUDE_PATHS=(
  "some-project/videos"        # フォルダごと除外
  "other-project/big-file.zip" # ファイル 1 つだけ除外
)
```

- `~/dev/` からの相対パスで書きます。`~/dev/...` や `$HOME/dev/...` から書いてもかまいません（先頭は取り除いて扱います）。
- そのパスだけが対象です。別の場所にある同じ名前のフォルダは除外しません（rsync と GNU tar）。
- `..` や `.` を含むパスはエラーになります。存在しないパスを書くと注意が出ます（書き間違いに気づけるように）。
- 実行のたびに、除外するパスの一覧を最初に表示します。
- **すでにバックアップ先にあるものは消えません。** rsync の `--delete` は除外したパスには効かないので、あとから除外に加えたものは、必要ならバックアップ先から手で消してください。
- macOS の tar（bsdtar）には先頭に固定するオプションがないため、tar モードでは別の場所にある `dev/<そのパス>` という並びも除外されます（実際に困ることはまれです）。rsync モードは macOS でも先頭に固定されます。

### rsync の保存先の目印

rsync は `--delete` を使うため、保存先の `dev/` に別のファイルがあると消してしまいます。これを防ぐため、`$BACKUP_DEST/dev/` に目印ファイル `.dev-backup` があるときだけ書き込みます。

- `dev/` が無い、または空なら、スクリプトが作って目印を置きます（初回は何もしなくてよい）。
- 中身のある既存の `dev/` で目印が無いときは、エラーで止まります。そのフォルダをバックアップ専用にしてよいと確認できた場合だけ、表示されるコマンド（`touch .../.dev-backup`）を実行してください。

## 実行ログ

rsync と tar を実行するたびに、`logs/backup.log`（git 管理外）へ 1 行追記します。

```
2026-11-11 14:30:00 rsync 成功 80秒 /path/to/backup
```

- 書式は「日時 モード 結果 所要秒数 保存先」です。
- 結果は `成功`、`警告(rsync rc=23)`（シンボリックリンクのスキップなど。想定内）、`失敗(rc=...)` のいずれかです。
- `check` と、保存先が無い・未設定・不明なモードで始まる前に止まった場合は記録しません。
- 最後に実行した日は `tail -3 logs/backup.log` で分かります。

## `~/dev/` から使えるようにする

スクリプト本体はこのリポジトリに置き、`~/dev/` にはシンボリックリンクを置きます。リンク経由で実行しても、本体の場所から `config/backup.conf` を探します。

```bash
ln -s ~/dev/dev-management/scripts/backup-dev.sh ~/dev/backup-dev.sh
```

既に同名のファイルがある場合は、先に退避してください。

## macOS で使うとき

スクリプトは WSL2（Ubuntu）で作ったものですが、macOS でも 3 モードとも動きます。ただし rsync モードには準備が要ります。

- **Homebrew の rsync を入れる。** macOS 標準の rsync（openrsync）は `--info=progress2` に対応しておらず、rsync モードはコピーを始める前にエラーで止まります。`check` と `tar` は標準のままで動きます。

  ```bash
  brew install rsync
  which rsync        # /opt/homebrew/bin/rsync と出れば、スクリプトからもこちらが使われる
  ```

- **cron や launchd で自動実行するときは PATH に注意する。** これらは `/opt/homebrew/bin` を PATH に含めないため、標準の rsync が使われて上と同じエラーになります。ターミナルから手で実行する分には問題ありません。
- **保存先は `/Volumes/ドライブ名/...` で指定する。** ドライブをつないでいないときは「バックアップ先が存在しません」で止まり、本体側には何も作りません。
- **`check` の件数の前に空白が入る。** 「未コミット:       1」のように表示されますが、macOS の `wc -l` の出力によるもので、判定は正しく動きます。
- **macOS 12.3 以降が必要。** シンボリックリンク経由の実行で使う `readlink -f` が、それより前の macOS にはありません。

## 注意

- rsync は `--delete` 付きです。`~/dev/` で消したファイルは、次回の実行でバックアップ先からも消えます。過去の状態を残したいときは tar を使ってください。
- tar は古いファイルを自動で消しません。実行のたびに保存先の直下に増えるので、不要になったものは手動で整理してください。
- Windows のドライブ（`/mnt/*`）はシンボリックリンクを作れないため、rsync が「一部スキップ」の警告（終了コード 23）を出すのは正常です。
- git 確認は、`~/dev/` から 3 階層までのリポジトリが対象です。
