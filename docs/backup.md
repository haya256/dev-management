# ~/dev のバックアップ

`scripts/backup-dev.sh` は、`~/dev/` をまるごと外付けドライブなどへバックアップするスクリプトです。

## モード

```bash
bash scripts/backup-dev.sh          # 差分コピー (rsync)。バックアップ先の dev/ を ~/dev/ と同じ状態にする
bash scripts/backup-dev.sh tar      # 日時付きの tar.gz を 1 ファイル作る
bash scripts/backup-dev.sh check    # 未コミット・未 push のリポジトリを確認するだけ（バックアップ先は不要）
```

どのモードでも、最初に各 git リポジトリの未コミット・未 push を表示します。
`node_modules` や `.venv` など再生成できるものと `certs` は除外します（一覧はスクリプト内の `EXCLUDES`）。

## 設定

バックアップ先は PC ごとに違うため、リポジトリには書きません。次のどちらかで指定します。

- `config/backup.conf`（git 管理外）に書く:

  ```bash
  BACKUP_DEST=/path/to/backup
  ```

- 環境変数で指定する: `BACKUP_DEST=/path/to/backup bash scripts/backup-dev.sh`

`BACKUP_DEST` は**保存先フォルダ**です。この中にバックアップができます。保存先より上の階層には何も書きません。

`BACKUP_DEST=/X/backup` の場合:

| モード | できるもの | 備考 |
|---|---|---|
| rsync | `/X/backup/dev/` | `~/dev` の中身がこの `dev/` 直下に入る（`dev/dev/` にはならない） |
| tar | `/X/backup/dev-20261111-1430.tar.gz` | 保存先の直下に 1 ファイル。中身は `dev/` から始まる |

- ドライブ直下や、名前が `dev` のフォルダは指定しないでください（ドライブ直下に `dev/` や tar ができる、`dev/dev/` と二重になる）。専用のサブフォルダを作って指定してください。
- **`BACKUP_DEST` は自動では作りません。** 外付けドライブが接続されていないときに、本体側へ偽のバックアップ先を作ってしまうのを防ぐためです。初回は手動で作成してください。存在しなければスクリプトはエラーで止まります。

### rsync の保存先の目印

rsync は `--delete` を使うため、保存先の `dev/` に別のファイルがあると消してしまいます。これを防ぐため、`$BACKUP_DEST/dev/` に目印ファイル `.dev-backup` があるときだけ書き込みます。

- `dev/` が無い、または空なら、スクリプトが作って目印を置きます（初回は何もしなくてよい）。
- 中身のある既存の `dev/` で目印が無いときは、エラーで止まります。そのフォルダをバックアップ専用にしてよいと確認できた場合だけ、表示されるコマンド（`touch .../.dev-backup`）を実行してください。

## `~/dev/` から使えるようにする

スクリプト本体はこのリポジトリに置き、`~/dev/` にはシンボリックリンクを置きます。リンク経由で実行しても、本体の場所から `config/backup.conf` を探します。

```bash
ln -s ~/dev/dev-management/scripts/backup-dev.sh ~/dev/backup-dev.sh
```

既に同名のファイルがある場合は、先に退避してください。

## 注意

- rsync は `--delete` 付きです。`~/dev/` で消したファイルは、次回の実行でバックアップ先からも消えます。過去の状態を残したいときは tar を使ってください。
- tar は古いファイルを自動で消しません。実行のたびに保存先の直下に増えるので、不要になったものは手動で整理してください。
- Windows のドライブ（`/mnt/*`）はシンボリックリンクを作れないため、rsync が「一部スキップ」の警告（終了コード 23）を出すのは正常です。
- git 確認は、`~/dev/` から 3 階層までのリポジトリが対象です。
